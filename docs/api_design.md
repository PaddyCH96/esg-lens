# API Design — ESG Lens

- Base path: `/api/v1`
- Content type: `application/json`
- Auth: **none in v1** (localhost tool). Design endpoints so a header-based key can be added later.
- Errors: RFC-7807-shaped problem objects.
- OpenAPI: auto-generated by FastAPI at `/docs` and `/openapi.json`.

---

## Conventions

**Ticker format:** `^[A-Z0-9.\-]{1,10}$`, uppercased server-side. Invalid → `422`.

**Error envelope**
```json
{
  "type": "https://esg-lens.dev/errors/ticker-not-found",
  "title": "Ticker not found",
  "status": 404,
  "detail": "No company record for 'ZZZZ'. Run POST /api/v1/portfolio/analyze first.",
  "instance": "/api/v1/company/ZZZZ/score"
}
```

| Status | When |
|---|---|
| 200 | OK |
| 202 | Job accepted |
| 400 | Malformed body |
| 404 | Unknown job or ticker |
| 409 | Concurrency limit reached (a job is already running) |
| 422 | Validation failure (bad ticker, too many tickers) |
| 429 | Client rate limit exceeded |
| 500 | Unhandled |
| 503 | Models still loading (during startup) |

## 1. `POST /api/v1/portfolio/analyze`

Queues an analysis. Returns immediately — **never blocks on NLP**.

**Request**
```json
{
  "tickers": ["AAPL", "XOM", "JPM"],
  "force_refresh": false,
  "lookback_days": 365,
  "sources": ["gdelt", "edgar", "yfinance"]
}
```

| Field | Type | Req | Default | Notes |
|---|---|---|---|---|
| `tickers` | `string[]` | ✅ | — | 1–25 items, deduped, uppercased |
| `force_refresh` | `bool` | ✗ | `false` | Bypass the HTTP cache and re-collect |
| `lookback_days` | `int` | ✗ | `365` | 30–730 |
| `sources` | `string[]` | ✗ | all enabled | Subset of `gdelt`, `edgar`, `yfinance`, `newsapi`. Must match the `raw_documents.source` CHECK exactly — adding a collector means updating both. |

**`202 Accepted`**
```json
{
  "job_id": "8f14e45f-ceea-467a-9c1b-3f2a1c0d5e77",
  "status": "queued",
  "tickers": ["AAPL", "XOM", "JPM"],
  "n_total": 3,
  "created_at": "2026-09-02T14:03:11Z",
  "estimated_seconds": 45,
  "links": {
    "status": "/api/v1/portfolio/8f14e45f-ceea-467a-9c1b-3f2a1c0d5e77"
  }
}
```

**`422`** — empty list, >25 tickers, or a malformed symbol.
**`409`** — `max_concurrent_jobs` reached; body includes `retry_after_seconds`.

## 2. `GET /api/v1/portfolio/{job_id}`

Poll for progress. Clients should poll every 2–5 s.

**`200` — running**
```json
{
  "job_id": "8f14e45f-ceea-467a-9c1b-3f2a1c0d5e77",
  "status": "running",
  "progress": {
    "completed": 1, "failed": 0, "total": 3, "percent": 33.3,
    "current_ticker": "XOM", "current_stage": "nlp"
  },
  "created_at": "2026-09-02T14:03:11Z",
  "started_at": "2026-09-02T14:03:12Z",
  "finished_at": null,
  "items": [
    {"ticker": "AAPL", "status": "done",    "n_documents": 47, "score": 62.4, "error": null},
    {"ticker": "XOM",  "status": "running", "n_documents": 51, "score": null, "error": null},
    {"ticker": "JPM",  "status": "pending", "n_documents": 0,  "score": null, "error": null}
  ],
  "error": null
}
```

**`200` — done** (`status` ∈ `done` | `partial` | `failed` | `cancelled`)
```json
{
  "job_id": "8f14e45f-ceea-467a-9c1b-3f2a1c0d5e77",
  "status": "partial",
  "progress": {"completed": 2, "failed": 1, "total": 3, "percent": 100.0,
               "current_ticker": null, "current_stage": null},
  "finished_at": "2026-09-02T14:04:02Z",
  "items": [
    {"ticker": "AAPL", "status": "done",   "n_documents": 47, "score": 62.4, "error": null},
    {"ticker": "XOM",  "status": "done",   "n_documents": 51, "score": 20.7, "error": null},
    {"ticker": "JPM",  "status": "failed", "n_documents": 0,  "score": null,
     "error": "collector_error: all sources returned zero documents"}
  ],
  "summary": {
    "portfolio_score": 41.6,
    "weighting": "equal",
    "scored": 2, "unscored": 1
  },
  "links": {
    "scores": ["/api/v1/company/AAPL/score", "/api/v1/company/XOM/score"]
  }
}
```
`status = partial` means some tickers succeeded and some failed — the client must handle it.
`summary.portfolio_score` is an equal-weighted mean over `status="ok"` scores only; it is `null`
if fewer than one ticker scored. **`404`** if the job id is unknown. Jobs are retained **30 days**, enforced by the startup
retention sweep in `architecture.md` §5.4; `esg_scores.job_id` is `ON DELETE SET NULL`, so
purging a job never removes score history.

## 3. `GET /api/v1/company/{ticker}/score`

Returns the **latest stored** score. Read-only — it never triggers collection or NLP.

**Query params**

| Param | Type | Default | Notes |
|---|---|---|---|
| `include_evidence` | `bool` | `true` | Include `top_contributors` |
| `evidence_limit` | `int` | `5` | 0–20 |
| `as_of` | `date` | — | Latest score computed on or before this date |

**`200`**
```json
{
  "ticker": "XOM",
  "company": {
    "name": "Exxon Mobil Corporation",
    "sector": "Energy", "industry": "Oil & Gas Integrated",
    "country": "US", "market_cap": 465000000000
  },
  "score": {
    "composite": 20.7,
    "status": "ok",
    "confidence": 0.19,
    "sector_percentile": null,
    "pillars": {
      "E": {"score": 20.7, "penalty": 3.72, "n_signals": 2, "status": "ok"},
      "S": {"score": null, "penalty": 0.0, "n_signals": 0, "status": "insufficient_data"},
      "G": {"score": null, "penalty": 0.0, "n_signals": 1, "status": "insufficient_data"}
    },
    "pillar_weights": {"E": 1.0, "S": 0.0, "G": 0.0},
    "pillar_weights_note": "Renormalised over pillars with sufficient data (base Energy weights E .50 / S .25 / G .25)."
  },
  "evidence": {
    "n_documents_collected": 3,
    "n_documents_esg_relevant": 3,
    "window": {"start": "2025-09-02", "end": "2026-09-02"},
    "sources": {"gdelt": 3},
    "top_contributors": [
      {
        "signal_id": 8814,
        "pillar": "E", "category": "Pollution & Waste",
        "title": "Regulator fines Exxon Mobil over refinery leak",
        "url": "https://www.reuters.com/...",
        "domain": "reuters.com", "source_tier": 1,
        "published_at": "2026-08-23T09:12:00Z",
        "sentiment": -0.70,
        "controversy_severity": 2,
        "controversy_terms": ["fine", "leak"],
        "polarity": -0.81,
        "weight_evidence": 0.883,
        "weight": 0.265,
        "contribution": -31.1
      }
    ]
  },
  "benchmark": {
    "external_esg_score": 41.0,
    "external_esg_provider": "sustainalytics_via_yfinance",
    "note": "Not an input to the composite. Shown for comparison only."
  },
  "methodology": {
    "version": "1.0.0",
    "config_hash": "sha256:9a1f...",
    "docs_url": "/docs/scoring_methodology.md"
  },
  "computed_at": "2026-09-02T14:03:58Z",
  "is_stale": false

```

**`200` with `status: "insufficient_data"`** — `composite` is `null`, pillars present but null,
and `evidence` still returned so the caller can see *why*. This is a success, not an error.

**`404`** — the ticker has never been analysed; `detail` tells the caller to POST an analysis first.

## 4. Supporting endpoints

| Endpoint | Purpose |
|---|---|
| `GET /api/v1/healthz` | `{"status":"ok","db":"ok","models_loaded":true,"version":"1.0.0"}`; `503` while models load |
| `GET /api/v1/company/{ticker}/history?limit=30` | Score time series — free from the append-only table |
| `GET /api/v1/company/{ticker}/documents?pillar=E&included=true&limit=50` | Paginated raw evidence. **`pillar` and `included` are columns on `esg_signals`, not `raw_documents`** — the endpoint joins `raw_documents → esg_signals` and filters on the signal row whose `model_version` matches the one behind the ticker's latest `esg_scores` row. Documents with no signal row at that version are returned only when no filter is supplied. |
| `GET /api/v1/methodology` | Serves the resolved weights + version — makes transparency machine-readable |
| `DELETE /api/v1/portfolio/{job_id}` | **Deferred past v1.** Cancellation needs checkpoint semantics the job runner does not define (`architecture.md` §5.4 exposes only `enqueue`/`get`/`update`). The `cancelled` value stays in the `jobs.status` CHECK so adding it later needs no migration. Do not implement in Phase 4. |

## Client contract notes for the future dashboard
1. **Always poll.** Analysis is async; there is no synchronous scoring endpoint by design.
2. **Handle three score states:** `ok`, `insufficient_data`, `failed`. Never render `null` as `0`.
3. **Render `confidence` next to every score.** A 20.7 at confidence 0.19 must not look like a
   20.7 at confidence 0.9 — this is a product requirement, not a nicety.
4. **`sector_percentile` is the cross-company comparison field.** Raw composites are not
   comparable across sectors, because the pillar weights differ.
5. Generate the TypeScript client from `/openapi.json` rather than hand-writing types.
